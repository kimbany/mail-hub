# 메일 통합 조회

Gmail · 네이버 · 다음 · 카카오 · 네이트 메일 계정 여러 개를 한 화면에서 보고,
계정마다 받은메일을 규칙으로 분류하는 웹사이트입니다.
인터넷에 올려서 휴대폰·PC 어디서든 브라우저로 보거나, 내 PC에서만 실행할 수 있습니다.

## 인터넷에 올리기 (무료: Render + Neon)

설치할 것은 없고, 두 사이트에 가입만 하면 됩니다. 10분 정도 걸립니다.

1. **Neon (데이터 저장용, 무료)**
   1. https://neon.tech 에 GitHub 계정으로 가입합니다.
   2. 프로젝트를 만들 때 Region 은 **Asia Pacific (Singapore)** 를 고릅니다.
   3. 대시보드의 **Connect** 를 눌러 나오는 `postgresql://...` 주소를 복사해 둡니다.
2. **Render (사이트 실행용, 무료)**
   1. https://render.com 에 GitHub 계정으로 가입하고, `mail-hub` 리포 접근을 허용합니다.
   2. 아래 링크를 엽니다.
      https://render.com/deploy?repo=https://github.com/kimbany/mail-hub
   3. 입력칸 두 개를 채우고 **Deploy** 를 누릅니다.
      - `SITE_PASSWORD`: 사이트에 들어갈 때 쓸 비밀번호 (길고 어렵게)
      - `DATABASE_URL`: 1번에서 복사한 Neon 주소
   4. 몇 분 뒤 `https://mail-hub-xxxx.onrender.com` 같은 주소가 생깁니다. 그 주소를 휴대폰 홈 화면에 추가해 두면 앱처럼 쓸 수 있습니다.

알아둘 점

- 무료 플랜은 15분 동안 아무도 안 들어오면 잠듭니다. 다음에 열 때 30초~1분 정도 기다리면 깨어납니다.
  항상 켜 두려면 Render 에서 플랜을 Starter(월 약 7달러)로 바꾸면 됩니다.
- 메일 서버 입장에서는 **싱가포르 서버에서 로그인**하는 것이 됩니다.
  네이버의 "해외 로그인 차단"을 켜 두셨다면 꺼야 하고, Gmail 은 처음에 보안 알림이 올 수 있습니다 (본인 맞음으로 확인).
- `MASTER_KEY` 는 Render 가 만들어 줍니다. Render 서비스를 지우고 새로 만들면 키가 바뀌므로, 메일 계정을 다시 추가해야 합니다.
- 코드를 GitHub `main` 에 올리면 Render 가 자동으로 다시 배포합니다.

## 내 PC 에서 실행

[Node.js](https://nodejs.org) 18 이상이 필요합니다.

```bash
npm install
npm start
```

브라우저에서 http://localhost:3000 을 엽니다. 처음 열면 사이트 비밀번호를 정하는 화면이 나옵니다.

## 메일 계정 준비 (IMAP 켜기)

| 메일 | 설정할 곳 | 비밀번호 칸에 넣을 것 |
|---|---|---|
| Gmail | Google 계정 → 보안 → 2단계 인증 켜기 → 앱 비밀번호 | 앱 비밀번호 16자리 |
| 네이버 | 메일 → 환경설정 → POP3/IMAP 설정 → IMAP 사용 | 2단계 인증 중이면 애플리케이션 비밀번호, 아니면 네이버 비밀번호 |
| 다음 | 메일 → 환경설정 → IMAP/POP3 → IMAP 사용 | 2단계 인증 중이면 앱 비밀번호 |
| 카카오메일 | 메일 → 환경설정 → IMAP/SMTP 사용 | 안내되는 앱 비밀번호 |
| 네이트 | 메일 → 환경설정 → POP3/SMTP/IMAP → IMAP 사용 | 네이트 비밀번호 |

"계정 추가" 때 실제로 로그인해 보고, 성공한 계정만 저장합니다.

## 전체 메일함

왼쪽 맨 위 **전체 메일함**을 누르면 모든 계정의 받은메일이 날짜순으로 한 목록에 모입니다.
메일마다 어느 계정에서 왔는지 표시되고, 연결이 안 되는 계정이 있으면 목록 위에 알려 줍니다.

## 분류 규칙

"분류 규칙"에서 `분류 이름 ← 보낸사람/받는사람/제목에 "글자" 포함` 규칙을 만듭니다.
위에서부터 처음 맞는 규칙의 분류로 들어가고, 맞는 규칙이 없으면 "미분류"입니다.
메일을 불러올 때마다 규칙이 자동으로 적용되고, 규칙을 바꾸면 이미 받은 메일에도 바로 반영됩니다.

- **계정별 분류**: 계정을 고르고 만든 규칙. 그 계정 메일함에서만 쓰입니다.
- **전체 분류**: 전체 메일함에서 만든 규칙. 모든 계정의 메일에 적용됩니다.
  예) `청구서 ← 제목에 "청구서"` 를 만들면 지메일·네이버·카카오 어디서 온 청구서든 한 분류에 모입니다.

두 가지는 따로 관리되므로, 같은 메일이 네이버 메일함에서는 "회사", 전체 메일함에서는 "청구서"로 보일 수 있습니다.
원래 메일 서버(네이버·Gmail 등)의 메일함은 건드리지 않습니다.

## 보안

- 메일 비밀번호는 AES-256-GCM 으로 암호화해서 저장합니다 (Postgres 또는 `data/store.json`).
  암호화 키는 저장소와 따로 둡니다: 환경변수 `MASTER_KEY`, 없으면 `data/secret.key` 에 자동 생성.
  그래서 DB 내용만 새어 나가서는 메일 비밀번호를 풀 수 없습니다.
- 사이트 비밀번호는 scrypt 해시로만 저장합니다.
- 내 PC 에서는 기본으로 `127.0.0.1` 에서만 열려서 PC 밖에서는 접속할 수 없습니다.
- 인터넷에 공개할 때(`HOST` 가 `127.0.0.1` 이 아닐 때)는 `SITE_PASSWORD` 가 없으면 시작하지 않습니다.
  모르는 사람이 먼저 사이트 비밀번호를 정해 버리는 것을 막기 위해서입니다. Render 는 HTTPS 를 자동으로 붙여 줍니다.
- 사이트 비밀번호를 5번 틀릴 때마다 15분 동안 로그인이 잠깁니다.
- 메일 본문 HTML 은 스크립트가 실행되지 않는 sandbox iframe 안에서 보여줍니다.
- `data/` 폴더는 git 에 올라가지 않습니다. 다른 사람에게 주지 마세요.

## 환경변수

| 이름 | 기본값 | 설명 |
|---|---|---|
| `PORT` | 3000 | 포트 |
| `HOST` | 127.0.0.1 (Render 에서는 0.0.0.0) | 접속 허용 주소 |
| `SITE_PASSWORD` | 없음 | 사이트 비밀번호. 인터넷 공개 시 필수 |
| `DATABASE_URL` | 없음 | 있으면 Postgres 에 저장, 없으면 `DATA_DIR` 파일에 저장 |
| `DATA_DIR` | `./data` | 저장 폴더 |
| `MASTER_KEY` | (자동 생성) | 메일 비밀번호 암호화 키. `DATABASE_URL` 을 쓸 때는 필수 |

## 앞으로 붙일 수 있는 것

- Gmail OAuth 로그인 (앱 비밀번호 없이)
- 받은메일함 외 다른 폴더, 검색, 읽음 처리, 메일 쓰기
